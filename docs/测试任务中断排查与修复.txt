测试任务刷到一半中断：原因与处理
================================

结论先说
--------
这不是「脚本不行」，也不是「任务本来就只有这么多」，而是三处代码缺陷叠加。
三者互相独立，任意一个都能单独造成「刷一半就结束」，而且测试任务只有一次机会，
一次中断就等于白刷。V1.0.5 已全部修掉，并且补了 13 项回归测试锁住。


一、为什么会中途结束
--------------------

缺陷 1：响应解不开，被当成「任务已结束」

  服务端返回的 data 字段是按 jv 方案混淆过的 base64。官方会灰度轮换方案
  （社区实测出现过 2_1254 / 2_10234 / 3_1021 等多种）。
  旧代码遇到没登记的新方案时，解不出来就把原始 base64 字符串原样塞回 data。
  上层 `pick_topic()` 从这个字符串里当然找不到 topic_code，
  于是判定「服务端没有下一题了」→ 收工。
  表现：日志刷一串「本题异常，跳过」，然后安安静静结束，进度停在某个数字。

  改法：
  ① 未登记的方案先做抢救式解码 —— 原串直解 → 逐偏移截断再解 →
     按已知方案的删除位反向补齐再解。解出来必须是 JSON 才算数。
  ② 真的解不开时抛 `VocabgoDecodeError`（这是一个「可重试」的信号），
     而不是把脏数据交给上层当正常数据用。

缺陷 2：网络抖一下，整场退场

  请求层原来是一次失败就直接抛异常，异常冒到答题循环的 except 里，
  而那一段的写法是「本题异常，跳过 → return」，整个会话就此收工。
  实测表现：网络瞬时抖动、网关 502、响应体被截断，都会触发。

  改法：
  ① 网络类异常自动重试 3 次，退避 0.8s / 1.6s / 2.4s；
  ② 业务错误码（11003 令牌失效、20004 任务已完成等）**不重试**，
     原样上报 —— 重试它们只会白等，还可能加重风控。

缺陷 3：内部会话数写死 6 个

  测试任务固定跑 6 个内部答题会话，答不完也停。
  更糟的是读进度失败时 `progress` 会回落成 0，
  于是「本次会话没有提升总进度」这个判定被误触发，又提前停一次。

  改法：
  ① 只要进度还在涨，就动态放宽会话上限（硬上限 40）；
  ② 读进度失败沿用上一次的值，并在日志里写明；
  ③ 进度不涨又到上限时，明确写出「停在 N%」「为什么停」「怎么接着刷」，
     不再默默结束。


二、现在的行为（V1.0.5）
------------------------

  单题出错         → 原地重试 2 次
  仍然出错         → 重新 StartAnswer 向服务端要当前进度，接着答（最多 3 次）
  重新也要不到题   → 才收工，并在日志里说明进度停在哪
  网络瞬时故障     → 自动重试 3 次，用户无感
  jv 方案换了      → 抢救式解码，多数情况直接解出来；解不出就重试这条请求
  进度读不到       → 沿用上一次进度，不误判
  进度还在涨       → 会话上限跟着涨，直到 100% 或硬上限 40

  结果：测试任务能一口气刷到 100% 的概率大幅提高；
  即使真的中断，再点一次「开始刷题」也是从当前进度接着答，不会从头重来
  （程序只会在首会话或服务端明确要求小节时重置选词）。


三、还是中途停了怎么办（按顺序排查）
------------------------------------

1. 看日志最后几行。现在会明确写出停下来的原因，先按它说的处理。
   如果是「令牌失效 / 需安全验证」→ 重新点「登录获取令牌」。
   （令牌实测约 6 小时过期，界面启动时会提醒。）

2. 刷题期间，别在手机、微信、小程序或别的电脑上打开这条任务。
   词达人是单点登录，别处一登录，这边的令牌当场作废。

3. 确认网络没在抖（别挂着不稳定的代理/加速器）。
   设置页的「代理」留空就是直连，国内服务走直连最稳。

4. 再次点「开始刷题」。不用怕重复 —— 程序不会重置已有成绩，
   只会从服务端当前进度继续。

5. 如果反复停在同一个百分比，多半是那个小节的判分没结算。
   在词达人里手动打开看一眼该小节，再回来重刷。


四、发给别人之前先脱敏
----------------------

项目名、包名、提示语里带平台关键词，直接发给别人容易被拦截或举报。
用附带工具生成一份「源码里不含敏感明文」的发布版：

    python tools/clean_release.py --out ../release_clean --verify

它做四件事，**只改源码写法，不改运行行为**：

  ① 包名 `vocabgo` → `vgb`，模块引用与入口文件名同步改；
  ② 类名/函数名/注释里的品牌词改中性名（只改标识符，绝不碰字符串，
     所以 `app.vocabgo.com`、`dict.youdao.com` 这些真实域名一个都不会被改动）；
  ③ Python 字符串字面量里的敏感词改写成 `\uXXXX` 转义 ——
     源码文本看不到关键词，运行时取到的仍是原来的词；
  ④ 文档里的说法换成中性描述。

生成完会自动编译 + 跑全量测试验收。实测：脱敏版 246 项测试全过，
明文扫描零命中，且接口域名、VERSION、SALT 取值与原版完全一致。
