V1.0.6
--
发布日期：2026-10-29

修复：从 GitHub「Download ZIP」下载的包，双击 启动.bat 直接崩

现象：双击 启动.bat 窗口闪一下、满屏乱码，程序根本起不来。
重装 Python、查杀毒软件都没用。

原因：仓库里存的 .bat 是 **LF 换行**，而 cmd.exe 解析「LF 换行 + 中文」的批处理时
会把行切断 —— 把 `echo 未找到本地 Python 环境...` 的后半截当成命令执行。
GitHub 的「Download ZIP」是在 Linux 服务器上生成归档的，原生换行就是 LF，
于是用户拿到的 .bat 全是 LF。

为什么作者自己测不出来：Git for Windows 默认 `core.autocrlf=true`，
自己 clone 下来时会被自动转成 CRLF，本机一切正常；而 ZIP 下载不走这套转换。

为什么只有部分同学遇到：GitHub 有两条下载路径，字节完全不同 ——

    仓库页「Download ZIP」  → LF   ❌
    Release 里的附件         → CRLF ✅
    git clone                → CRLF ✅（本机自动转换）

修复：新增 `.gitattributes`，把换行由属性写死，不再看机器配置、也不看平台：

    *.bat text eol=crlf

这样 checkout 和 git archive（= GitHub ZIP）一律输出 CRLF，三条路径全部正常。

顺带修复：prepare.bat 可能用没有 tkinter 的 Python 建环境

它原来只检查「版本存在」，不检查有没有 tkinter。有台机器装了 Python 3.13
但没装 tcl/tk，拿它建的 .venv 缺 tkinter，图形界面照样起不来 ——
表现和换行故障一模一样，极难排查。现在建环境前先验证 tkinter，
缺了就给出明确指引（重装 Python 并勾选 "tcl/tk and IDLE"）。
tkinter 没法用 pip 补装，所以必须换 Python。

注意：这几个 .bat 里的 `rem` 注释**一律用英文**。实测 UTF-8 批处理里
`rem` 加中文会让 cmd 把行切断、执行出乱码；中文说明只能放在 `echo` 里。

新增：任务体检（🩺 按钮）

开刷前点一下，就能看清这个任务的真实状态：进度、得分、累计用时、
单词分数分布、服务端还能不能出题。

为什么要它：测试任务一旦在答题中途被中断（断网、令牌失效、手动停止、触发风控），
服务端会把成绩**固定在断点处**，之后怎么刷都不动 —— 连官方小程序里手工做完
也报错、进度不变。以前只能靠「刷一轮试试」来判断，白耗时间。

体检会记下状态快照，再查一次就能对比：**进度和累计用时完全没变 = 已被固定**。
这是唯一可靠的判据 ——「服务端还能出题」不算数，被固定的任务照样出题。

修复：刷题时日志往上翻会被拽回底部

日志区原来每次写入都无条件滚到末尾，而刷题时每答完一个词就写一行，
所以想看前面答了什么，每 0.15 秒就被拉回去，根本看不了。
现在只有本来就停在末尾时才自动跟随；用户翻上去了就保持不动。

验证结果：

- 自动化测试：278 项通过（新增 15 项，覆盖日志滚动与任务体检）。
- 4 项可选 OCR 测试因本机没有 Tesseract 跳过。
- EXE 自检关键项通过。
- `.gitattributes` 实测：git check-attr 四个 bat 全部返回 eol=crlf；
  重新 clone 后落地换行均为 CRLF。
- prepare.bat 实跑通过（退出码 0）。
- 分享包不包含 config.json、bank.json、API Key 或个人数据。


V1.0.5
--
发布日期：2026-10-29

核心修复：测试任务不再「刷一半就结束」

测试任务只有一次机会，中途停下等于白刷。查下来是三处独立缺陷，都会单独造成这个现象：

- 响应解码失败被当成「任务结束」。服务端会灰度轮换 jv 混淆方案，
  没登记的方案原先会把原始 base64 串塞回 data，上层拿不到题目就把这一轮判成结束。
  现在新增抢救式解码（偏移截断 + 已登记规则的删除位反向补齐），
  真的解不开时抛 `VocabgoDecodeError`，由上层重试，不再污染正常流程。
- 网络抖一下也终止整场。请求层原来一次失败就抛，抛到答题循环里直接 return。
  现在网络类异常自动重试 3 次（0.8s 递增退避）；业务错误码（如 11003）不重试，原样上报。
- 单题异常让整个答题会话退场。现在同一题先原地重试 2 次，
  仍不行就重新 StartAnswer 向服务端要当前进度接着答（最多 3 次），
  只有真的拿不到题才收工。
- 测试任务的内部会话数原来死锁 6 个，答不完也收工。
  现在只要进度还在涨就放宽上限，硬上限 40；进度不涨又到上限时，
  明确写出停在几成、为什么停、怎么接着刷。
- 读取任务进度失败时，原来把 progress 回落成 0，于是「没进展」判定误触发。
  现在沿用上一次的进度，并在日志里标注。

新增

- `tools/clean_release.py`：生成「源码不含敏感明文」的发布版。
  只改变源码写法（Python 字符串改成 `\uXXXX` 转义、包名改中性名、标识符与注释改名），
  运行时取值完全不变；生成后自动编译并跑全量测试验收。

题型引擎：把「算得出来的题」从大模型手里拿回来

新增 `vocabgo/templates.py`，规则移植自社区维护最勤的实现（Easy_Cidaren 的题型分发），
按本项目的接口重写为纯函数、可单测。覆盖四类以前只能靠大模型猜的题：

- mode 73 多空首字母：题干是 `{gr}{sto}` 这种碎片前缀，`w_lens` 给出每空长度，
  答案按 JSON 数组提交。以前完全没处理，现在按「前缀 + 长度 + 任务词表」算出答案。
- mode 51~54 补全单词：服务端白送了 `w_tip`（前缀）和 `w_lens`（长度），
  和当前任务词表交叉一下答案基本唯一。以前丢给模型自由生成，常因词形不对被判错。
  内置词形扩展（复数/时态），所以词表给原形、题目要复数时也能答对。
- mode 41~44 补全句子：用中文备注与释义做重叠比对，命中即提交；题干固定词自动排除。
- mode 17/18 看义选词：题干是中文、选项是英文，反查释义表。

关键细节（都是踩过的坑）：

- 题干里的**固定词必须排除**，否则 `green {gr}{sto}` 里 `{gr}` 会命中 green，整题判错。
  排除还要穿透到词形扩展后的候选上，不然 `greens` 会绕过 `green` 的排除。
- 算不出来就返回 None，交回大模型/试答案链路，绝不硬猜。
- 兜底作答也要**格式正确**：多空首字母题必须提交等长 JSON 数组，格式错必然零分。

实测量化：用你本机落盘的失败样本结构做端到端验证，
四类真实题型（mode 51 单空 `str`+8 位、mode 51 `cho`+6 位、mode 73 双空、mode 51 复数扩展）
全部算对，统计记的是「题型模板 4 / LLM 0」—— 这四题一次大模型都没调用。

另外：失败样本落盘现在会记录 `w_tip`、`w_lens`、`w_len`。
以前不记，导致失败样本没法离线复现，也看不出模板为什么没命中。

验证结果：

- 自动化测试：263 项通过（新增 30 项：13 项中断韧性 + 17 项题型模板）。
- 4 项可选 OCR 测试因本机没有 Tesseract 跳过。
- EXE 自检关键项通过。
- 脱敏发布版：编译通过、263 项测试全过、明文扫描零命中、接口域名与签名常量实测未变。


V1.0.4
--
发布日期：2026-10-27

资料与识别：

- 支持直接导入 PNG、JPG、JPEG、BMP、WEBP、TIF、TIFF 图片资料。
- 图片 OCR 优先使用本地 Tesseract；本地不可用时回退到已配置的视觉模型。
- 图片资料支持多选；一次超过 20 张且会回退到视觉模型时，先提醒 token 消耗和等待时间。
- 服务端返回正确答案后，继续兼容空格和逗号两种短语提交格式。
- 短语选项中的全角空白会保留，避免 `sun　` 被裁剪成 `sun` 后提交失败。
- 短语题如果当前题状态暂时不判过，会缓存服务端回吐的正确答案，下一轮重刷优先提交。
- 填空答案支持按句子自动尝试常见复数词形，例如 `convention -> conventions`。
- 测试任务进度暂时不增长时会继续后续内部会话，直到服务端完成、进度到 100 或达到安全会话上限。
- 测试任务只在首会话或服务端明确要求小节时重置选词；后续会话不反复重置，避免从第一题重新开始。
- 设置页新增“检查更新”按钮，可随时手动检查 GitHub Release。

验证结果：

- 自动化测试：231 项通过。
- 4 项可选 OCR 测试因本机没有 Tesseract 跳过。
- EXE 自检关键项通过。


V4
--
发布日期：2026-10-26

填空题优化：

- 内部版本号统一为 `1.0.3`，与 GitHub 的 `V1.0.0 / v1.0.1 / v1.0.2` 发布序列保持一致。
- 新增 GitHub Release 更新检测：启动后后台检查新版本，可前往 GitHub 更新，也可选择忽略该版本。
- 设置页新增“检查更新”按钮，可随时手动检查，不受 24 小时自动检查间隔限制。
- 本地资料库支持直接导入 PNG、JPG、WEBP、BMP、TIFF 图片：优先调用本机 Tesseract，本地不可用时再自动走已配置的视觉模型。
- 图片资料支持多选导入；一次超过 20 张且会回退到视觉模型时，先弹窗提醒 token 消耗和等待时间。
- `mode=51` 把当前任务词表直接作为模型的答案候选范围，不依赖本地词库是否收录新词。
- 启动日志会显示“填空约束 v3”，失败样本也会记录 `prompt_version`，用于确认新代码是否已重新加载。
- 中文含义会先翻译成英文候选，再去掉题干里的固定部分，例如 `in batches` 会裁成 `batches`。
- 任务词表按原形提供，允许根据句子使用复数、时态等正确词形；服务端拒绝单数时会自动尝试常见复数形式（例如 `convention → conventions`）。
- 模型如果返回完整搭配，提交前会自动裁剪，只保留空格中的答案。
- `mode=32` 组词题支持 `sb.`、`sb.'s`、`times'`、`sth.`、`somebody` 等占位词归一，并修正兜底排序，避免把占位词放到错误位置。
- `mode=51` 提示词不再附带无关的 40 个旧单词释义，只保留当前题、中文含义和相关候选。
- 保持 `deepseek-flash` 和原来的三票投票，不额外增加每题的大模型调用次数。
- 填空题失败时写入 `failed_fill.jsonl`，记录题干、中文含义、候选、模型原始输出和服务端返回，便于离线复现。
- 服务端 `answer_result=2` 暂不当作成功，继续按未通过处理，避免错词被误判为完成而无法重刷。
- 班级学习任务由“班级学习轮数”控制，不再在单轮内部固定执行 6 个答题会话；测试任务仍保留最多 6 个内部会话以完成整套题。
- “允许重刷已完成学习任务”的勾选状态会持久保存，并在刷选中任务时明确记录是否生效；需要重刷 List 26 这类进度 100% 但仍有未满分词的任务时必须勾选。
- 单词语义按当前任务观察到的最高分自适应：最高 10 分就补低于 10 的词，最高超过 10 分则按实际最高分补词，避免固定阈值漏刷。
- 测试任务会保留全部词，允许部分词超过单词语义上限，从而用超分补足任务总分 100。
- 服务端返回 `answer_corrects` 时，会依次尝试原始空格格式和逗号格式，兼容 `orbit the sun` 与 `orbit,the,sun` 两种提交形式。

验证结果：

- 自动化测试：229 项通过。
- 可选 OCR 测试：4 项因本机没有 Tesseract 跳过。
- 在线小样本：3 道已知答案填空题，优化前 2/3 通过，优化后 3/3 通过。
- 在线复验：7 道实际被服务端拒绝的填空题，加入任务词表约束后 7/7 通过。
- 在线复验：`引用某人的话` 正确解析为 `quote,sb.`。
- 在线复验：`violate,sb.'s,privacy`、`for,old,times',sake`、`orbit,the,sun` 均正确解析。
- 示例提示词字符数从 696 降到 147。


V3
--
发布日期：2026-10-19

新增功能：

- 本地资料库：支持 TXT、MD、CSV、JSON、DOCX、EPUB 和文字型 PDF。
- 自动识别词表、短语和教材正文。
- 明确命中的题目由脚本直接作答，不调用大模型。
- 无法确定时只发送少量相关片段，不上传整本电子书。
- PDF 资料解析使用 pypdf。
- 自适应思考模式：基础题先关闭思考，答案不稳定时再开启思考重试。
- 句中专词义且没有本地证据时，直接使用思考模式。
- 分享版文档改为 manual.html，可通过 open_manual.bat 使用浏览器打开，不需要 Typora。
- 技术资料合并为 技术说明.txt。
- 新增本版本记录文件。

保留功能：

- 班级任务、学习任务和自学任务自动答题。
- 本地题库累积和按题目内容复用。
- 批量任务、自动续答和按阈值重练。
- 单实例保护，避免多个窗口同时写题库。
- 自动下载并校验官方 Python。
- 免安装 EXE。

验证结果：

- 自动化测试：202 项通过。
- 可选 OCR 测试：4 项因本机没有 Tesseract 跳过。
- EXE 自检：通过。
- PDF 解析组件：通过。
- 本地资料目录写入：通过。
